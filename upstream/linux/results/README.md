# A/B/C trace summaries

Generated by `../rig/run-trace.sh` against a 1280x800 virtio-vga dumb
buffer guest (`../../qemu/rig/guest/init.c`) marking a 480x360 region
dirty at 30 fps plus an 80x28 region once a second, with
`-trace virtio_gpu_cmd_res_flush -trace virtio_gpu_cmd_res_xfer_toh_2d`.
Only the summary each run prints (top `res_flush` geometries by count)
is kept here; the full `trace.log` files (57-59 KB of raw trace lines)
are not, per `../../README.md`.

- **A-debian-stock**: the guest's own Debian 6.12.101 `drm_kms_helper.ko`
  and `virtio-gpu.ko` (bug present).
- **B-rebuilt-unfixed**: `drm_kms_helper.ko` rebuilt from the same
  source, unpatched (`../rig/build-module.sh`'s `drm_kms_helper-stock.ko`)
  -- a control for the rebuild itself, not just the patch.
- **C-rebuilt-fixed**: the same rebuild with `../series/v1/`'s patch
  applied (`drm_kms_helper-fix.ko`).

`res_xfer_toh_2d` trace lines carry a timestamp and resource id but no
geometry, so `run-trace.sh`'s "top geometries" grouping is not
meaningful for it (it groups by timestamp, one line per count); this
summary keeps only `res_flush`, which is what the patch's commit
message and `../series/v1/*.patch` measure.
